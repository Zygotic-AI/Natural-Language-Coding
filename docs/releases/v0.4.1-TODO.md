# v0.4.1 approved order

SSOT for the approved v0.4.1 produce order on `release/v0.4.1`. This file lists the work and the order. It does not implement the items.

Rationale: v0.4.0 left the whole-tree digest in the signed gate set (PR #30 defect). The v0.4.1 line also carries the fail-open release-tool sweep from RCA PR #35, plus later CI, drill, and naming work. One order file keeps that sequence from being re-sorted in chat.

Related: [`docs/rca/2026-10-25-signed-whole-tree-digest.md`](../rca/2026-10-25-signed-whole-tree-digest.md) (PR #30), `docs/rca/2026-10-25-start-release-gh-missing-fail-open.md` (PR #35, not yet on this line), [`docs/adoption/RELEASE.md`](../adoption/RELEASE.md) (release checklist), [`docs/adoption/RELEASE-v0.4.0.md`](../adoption/RELEASE-v0.4.0.md).

Version class: patch (order record only).

## Approved order

Do these in this sequence. Do not reorder.

### 1. hub-content-tree-hash out of the gate set (PR #30 defect) plus checklist rule

Option A from the PR #30 RCA: keep the whole-tree freshness stamp `integrity/hub-content-tree-hash.txt`, take it out of the owner-signed gate set so routine content PRs no longer require a new owner signature, and do not weaken any other gate.

Also add the checklist rule to the release checklist doc (`docs/adoption/RELEASE.md`): a content-only change must not require a new owner gate-set signature, while a change to a real gate-set file still fails closed (missing tool, empty result, or unknown result counts as false).
