## What a review PR is (code already on `release/v0.3.0`)

The sync-up **code is already merged** on the release branch. A **review PR** does **not** re-land the 548-path bundle. It:

1. **Records** the review outcome (checklist, verdict table, links to evidence runs).
2. Applies **Change** or **Go** edits discovered during review (docs, gates, fixtures, receipts) plus tests/landmines that prove those edits.
3. Updates **FINDINGS** / ADR enforcement rows when a gap is closed or reclassified (after O10 gap SSOT merges).

**Verdict carry-out**

| Verdict | Action in the review PR |
| -------- | ------------------------ |
| **Go** | Merge the review PR with notes only (no functional diff), or empty merge commit on a `review/rN-*` branch if your forge requires a PR artifact. |
| **Change** | Same PR carries the fix + fitness/landmine proof; link the failing repro in the PR body. |
| **Block** | Do not merge; open a scoped implementation PR; leave FINDINGS row open. |

Each theme **R1–R6** maps to one or more review PRs; themes may run in parallel after **R1** receipts are understood.
