# Full text of adrs/0001-zero-variance-integrity.md
# # [ADR](../docs/TERMS.md#adr) 0001 — [Zero-variance](../docs/TERMS.md#zero-variance) [integrity](../docs/TERMS.md#integrity) for [Boundary-Based Programming](../docs/TERMS.md#bbp)
#
# - Status: Accepted
# - Date: 2026-09-04
# - Deciders: owner
#
# ## Context
#
# ADRs alone do not keep a practice honest. The [BBP](../docs/TERMS.md#bbp) [hub](../docs/TERMS.md#hub) must stand alone (own branding, own artifacts). Every [requirement](../docs/TERMS.md#requirement) and every prescribed [action](../docs/TERMS.md#action) must be auditable with a binary outcome. Unbound requirements and wish-level rules are defects, not backlog flavor.
#
# ## Decision
#
# 1. **Stand-alone branding.** [BBP](../docs/TERMS.md#bbp) owns its names, packages, and paths. External systems may be studied. If a shape is useful, copy and re/unbrand it into this repo. Do not import foreign brand packages or leave foreign brand names in [BBP](../docs/TERMS.md#bbp) artifacts.
#
# 2. **[Zero variance](../docs/TERMS.md#zero-variance).** Every [action](../docs/TERMS.md#action) by human or agent that changes this practice or an adopting system under [BBP](../docs/TERMS.md#bbp) is dictated and prescribed. Informal “judgment calls” that skip a prescribed [gate](../docs/TERMS.md#gate) are failures.
#
# 3. **Hard gates.** Every step and every [action](../docs/TERMS.md#action) has a hard [gate](../docs/TERMS.md#gate) that can be audited as **complete** or **incomplete** (no partial credit).
#
# 4. **Hard boundaries.** Every [boundary](../docs/TERMS.md#boundary) declares hard input and output contracts, including whether it throws, returns an error result, or exits the process (when the boundary is code).
#
# 5. **Binary [requirement](../docs/TERMS.md#requirement) audits.** Every [requirement](../docs/TERMS.md#requirement) in this repo has an [audit](../docs/TERMS.md#audit) that can binarily determine **[met](../docs/TERMS.md#met)** or **not [met](../docs/TERMS.md#met)**. A [requirement](../docs/TERMS.md#requirement) without such an [audit](../docs/TERMS.md#audit) is not a [requirement](../docs/TERMS.md#requirement) yet — it is unbound.
#
# 6. **[Binding matrix](../docs/TERMS.md#binding-matrix).** All requirements appear in the [binding matrix](../docs/TERMS.md#binding-matrix) with an [audit](../docs/TERMS.md#audit) id and a binder (check, confirmer step, or gate). An [audit](../docs/TERMS.md#audit) of the matrix **fails** if any entry is unbound. An [audit](../docs/TERMS.md#audit) of the matrix **lists** every unbound entry.
#
# 7. **Promote-only-when-bindable.** A [requirement](../docs/TERMS.md#requirement) may be promoted into the [charter](../docs/TERMS.md#charter) (or other in-force surface) only when a binder exists that can fail. The promote [audit](../docs/TERMS.md#audit) **fails** and **lists** any in-force [requirement](../docs/TERMS.md#requirement) that is not bindable.
#
# ## Consequences
#
# - [Charter](../docs/TERMS.md#charter) gains confirmable rules for practice [integrity](../docs/TERMS.md#integrity) (see §5.8).
# - `integrity/binding-matrix` becomes mandatory SSOT for [requirement](../docs/TERMS.md#requirement) → [audit](../docs/TERMS.md#audit) → binder.
# - Tools and [confirmer](../docs/TERMS.md#confirmer) packs must emit PASS/FAIL with evidence pointers; “looks good” is not an outcome.
# - Wish-level prose stays in `theory/` until bindable.
#
# ## Rejected
#
# - Importing foreign-branded packages as dependencies of [BBP](../docs/TERMS.md#bbp) [integrity](../docs/TERMS.md#integrity).
# - Tolerating unbound [charter](../docs/TERMS.md#charter) rules as “aspirational.”
# - Soft/warn-only gates as satisfaction of a hard [gate](../docs/TERMS.md#gate).

# # [ADR](../docs/TERMS.md#adr) 0002 — Scope of P2 (zero variance)
#
# - Status: Accepted
# - Date: 2026-09-04
# - Deciders: owner
# - Class: F (charter clarification)
#
# ## Context
#
# P2 currently reads as “every [action](../docs/TERMS.md#action) that changes an adopting [BBP](../docs/TERMS.md#bbp) system is prescribed.” That is correct for this [hub](../docs/TERMS.md#hub)’s [requirement](../docs/TERMS.md#requirement) loop and for class A/B (and D/E/F) gates. Applied to all coding motion it becomes governance under a new name. Agents need prescribed boundaries, not a script for every keystroke.
#
# [ADR](../docs/TERMS.md#adr) 0001 decision 2 and `integrity/PRINCIPLES.md` P2 can be over-read as: every edit is a gated procedure.
#
# ## Decision
#
# P2 binds:
#
# - (a) changes to the practice [hub](../docs/TERMS.md#hub)’s in-force surfaces and [integrity](../docs/TERMS.md#integrity) machinery, and
# - (b) the prescribed agent-loop **gates** for change classes A, B, D, E, F.
#
# P2 does not require a prescribed [action](../docs/TERMS.md#action) for every edit inside an already-ratified noun-verb or [goal](../docs/TERMS.md#goal) implementation.
#
# Unprescribed **[boundary](../docs/TERMS.md#boundary) crossings** remain incomplete work.
#
# ## Consequences
#
# - Update P2 [audit](../docs/TERMS.md#audit) language so “unprescribed [action](../docs/TERMS.md#action)” means “skipped a required [gate](../docs/TERMS.md#gate) or crossed a [noun](../docs/TERMS.md#noun) [boundary](../docs/TERMS.md#boundary) without a verb,” not “wrote code without a ticket.”
# - [Charter](../docs/TERMS.md#charter) §5.8 cites this [ADR](../docs/TERMS.md#adr) for P2 scope. [Rule](../docs/TERMS.md#rule) numbers are unchanged.
# - P2 remains unbound in the [binding matrix](../docs/TERMS.md#binding-matrix) until a fail-capable binder exists.
#
# ## Rejected
#
# - “Every keystroke is a gated procedure.”

# # [ADR](../docs/TERMS.md#adr) 0003 — Systems extension: [agent nouns](../docs/TERMS.md#agent-noun) and contracted verbs
#
# - Status: Accepted
# - Date: 2026-09-05
# - Deciders: owner
# - Class: F (charter extension)
#
# ## Context
#
# [BBP](../docs/TERMS.md#bbp) originated as a software practice: nouns own state and adjectives, verbs are the only legal mutation, goals orchestrate I/O, workflows compose goals. This model shrinks the search space for agents editing code.
#
# The same structural discipline applies to organizing agent fleets and durable roles in a system. Without boundaries, agent responsibilities blur. Handoffs become implicit. Completion is vibes. [Audit](../docs/TERMS.md#audit) trails scatter.
#
# Decision KD-005 (Koan): Start with [BBP](../docs/TERMS.md#bbp) as systems model. Nouns = durable agents/roles; verbs = legal functions; goals/workflows = use-cases; [boundary](../docs/TERMS.md#boundary) artifacts = [handoff](../docs/TERMS.md#handoff), completion definition, auditable success (ops vs defects).
#
# [Quality](../docs/TERMS.md#quality) north star: highest [quality](../docs/TERMS.md#quality); effectiveness before efficiency; [default-closed](../docs/TERMS.md#default-closed) (deny until evidence); DFSS; measure ops vs defects.
#
# ## Decision
#
# ### 1. Vocabulary mapping
#
# | Software [BBP](../docs/TERMS.md#bbp) | Systems [BBP](../docs/TERMS.md#bbp) |
# |--------------|-------------|
# | [Noun](../docs/TERMS.md#noun) | [Agent noun](../docs/TERMS.md#agent-noun) (durable role with identity and adjectives) |
# | [Verb (on noun)](../docs/TERMS.md#verb-on-noun) | Verb (legal function an agent may perform; contracted I/O) |
# | [Goal](../docs/TERMS.md#goal) | Use-case (orchestration across agent nouns or to the outside world) |
# | [Workflow](../docs/TERMS.md#workflow) | [Workflow](../docs/TERMS.md#workflow) (durable composition of use-cases) |
# | [Contract](../docs/TERMS.md#contract) | [Boundary artifact](../docs/TERMS.md#boundary-artifact) (input, output, failure mode, handoff, completion) |
# | [Adjective](../docs/TERMS.md#adjective) | Role [adjective](../docs/TERMS.md#adjective) (what the agent must never violate) |
# | [Gate](../docs/TERMS.md#gate) | [Gate](../docs/TERMS.md#gate) (automated enforcement; binary pass/fail; CI-bound) |
# | Adversarial review | [Audit](../docs/TERMS.md#audit) (role-based review against charter; produces findings) |
#
# ### 2. [Agent noun](../docs/TERMS.md#agent-noun) structure
#
# Every [agent noun](../docs/TERMS.md#agent-noun) package declares:
#
# - **Identity:** Role name, purpose (one line)
# - **Adjectives:** What the agent must never violate
# - **Verb list:** Each verb has input [contract](../docs/TERMS.md#contract), output [contract](../docs/TERMS.md#contract), failure mode
# - **Handoff-in:** What must be true before this agent receives work
# - **Completion artifact:** What the agent produces to mark work complete
# - **Success criteria:** Ops vs defects; binary auditable outcomes
#
# ### 3. Produce ≠ [Audit](../docs/TERMS.md#audit) (charter §7 extension)
#
# An agent that produces an artifact may not be the final auditor of that artifact. The agent that ships (ratifies, merges, releases) may not be the agent that grades itself. Separate produce, [audit](../docs/TERMS.md#audit), and [ship](../docs/TERMS.md#ship).
#
# ### 4. No shipping authority for [audit](../docs/TERMS.md#audit) roles
#
# [Agent nouns](../docs/TERMS.md#agent-noun) whose purpose is adversarial review, [audit](../docs/TERMS.md#audit), or standards enforcement do **not** have shipping authority (no `ratify`, `merge`, `release` verbs). They produce findings. Another role (or human) decides whether findings block the [ship](../docs/TERMS.md#ship).
#
# ### 5. [Charter](../docs/TERMS.md#charter) section
#
# A new [charter](../docs/TERMS.md#charter) section (§16 or similar) documents the systems model without altering the software rules in §§4–5.
#
# ## Consequences
#
# - [Charter](../docs/TERMS.md#charter) gains a "Systems / [agent nouns](../docs/TERMS.md#agent-noun)" section with vocabulary mapping and produce≠[audit](../docs/TERMS.md#audit)≠[ship](../docs/TERMS.md#ship) constraint.
# - `agents/` gains structured [agent noun](../docs/TERMS.md#agent-noun) packages (not just role prompts) with declared boundaries.
# - Existing software [BBP](../docs/TERMS.md#bbp) rules unchanged in meaning; systems layer is additive.
# - Three [agent nouns](../docs/TERMS.md#agent-noun) implement [Produce ≠ Audit ≠ Ship](../docs/TERMS.md#produce-audit-ship): standards-steward (produce standards), adversarial-auditor (audit), ship-role (authorize release).
#
# ## Rejected
#
# - Branding the systems model as "governance" (charter §3 naming).
# - Conflating [agent nouns](../docs/TERMS.md#agent-noun) with existing role packs (proposer/reviewer/confirmer/recorder are loop roles; agent nouns are durable organizational positions).
# - Granting [audit](../docs/TERMS.md#audit) roles any [ship](../docs/TERMS.md#ship) authority.
#
# ## Related
#
# - [Charter](../docs/TERMS.md#charter) §§3–7 (naming, core model, rules, agent loop, agent roles)
# - [`integrity/PRINCIPLES.md`](../integrity/PRINCIPLES.md) — produce≠[audit](../docs/TERMS.md#audit) aligns with P2/P3 (zero variance, hard gates)
# - KD-005 (Koan decision: BBP as systems model)

# # ADR 0050 — Evidence identity: content, not history
#
# - Status: Accepted
# - Date: 2026-10-10
# - Deciders: Human manager
# - Ratified-by: Human manager (evidence identity content-not-history ADR, 2026-10-10)
# - Class: F (integrity / gates), A (release and audit evidence)
# - Corpus: nlc
# - RCA: docs/rca/2026-10-10-sha-pinned-evidence-history-rewrite.md (instance record; analysis in operator packet)
#
# ## Context
#
# Hub proof mixed two evidence regimes: content fingerprints (for example `.nlc/verified.json`, release `effective_tree_sha`) and git commit ids (`last_pass_sha`, `audit_sha`, landmine `BAD_COMMIT`, `prepare_head`). An unstated assumption treated history as immutable and complete. When history was rewritten with identical trees, gates that depended on commit ids changed verdict without any content change. Earlier shallow-clone failures were fixed by requiring full clones instead of changing what evidence binds to.
#
# [`MANIFESTO.md`](../MANIFESTO.md) states that code is not the product — intent and emitted content are. [ADR 0007](0007-tags-primitives-reduced-adrs.md) requires naming facts the factory relies on. [`integrity/ACTIONS.md`](../integrity/ACTIONS.md) requires **REFUSE** when a check cannot run, not a substantive finding on unread input.
#
# ## Named facts
#
# 1. **History may change.** Rewrites, shallow clones, and mirrors can change commit ids while preserving tree content.
# 2. **A verdict is a pure function of (tree under test, gate set).** No gate outcome may depend on git history identity, clone depth, remote layout, or machine state unless that input is declared in the gate set and recorded in the receipt.
# 3. **Labels resolve at check time.** Tags, semver strings, and branch names are human labels resolved when the gate runs; they are not stored as proof handles.
#
# ## Decision
#
# 1. **Evidence binds to content.** Evidence records and fixtures name what was checked: git tree hash (40 hex), blob or path content digests, gate-set hash, and hub version — never a commit id as proof.
# 2. **Unresolvable input → REFUSE.** When a gate cannot resolve a declared reference (missing object, dangling label), it stops with **REFUSE** and prints the unresolved reference. It does not emit NOT_MET/FAIL for a different substantive reason.
# 3. **Freshness is content freshness.** “Fresh” means the recorded content hash equals the current content hash of the audited paths, not “an ancestor of HEAD”.
# 4. **Landmines are self-contained.** Designed-fail fixtures build the world they test (synthetic repository or tree) and assert the specific failure token. Passing for any other reason is a defect.
# 5. **Enforcement.** Hub CI runs: `fitness-no-history-ids-in-evidence`, `fitness-landmine-self-contained`, `assert-unresolvable-refuses-passes`, and a history-rewrite invariant job that must yield the same fitness verdict before and after rewriting a scratch copy (including shallow clone).
#
# ## Consequences
#
# - Evidence JSON schemas and FINDINGS headers use `*_tree_hash` (or path digests), not `*_sha` commit fields.
# - Release prepare receipts cite `integrity/hub-content-tree-hash.txt`, not `prepare_head`.
# - `fetch-depth: 0` is no longer required to keep SHA-pinned landmines green; shallow clones must MET when content is unchanged.
# - Provenance under `docs/history/` and `docs/rca/` may retain historical commit citations; operational gates do not read them.
#
# ## Rejected
#
# - **Environment-only fix (full clone forever):** repeats the 2026-09-25 accommodation; does not name the assumption ([`MANIFESTO.md`](../MANIFESTO.md) climb-upstream rule).
# - **Dual commit + tree fields:** forks evidence identity; rewrite still leaves commit field false.
# - **Optional migration window for commit ids in gates:** would leave two truths on identical trees.
#
# ## Related
#
# - [ADR 0005](0005-ssot-exit-evidence.md) — produce package evidence (abstract fields)
# - [ADR 0007](0007-tags-primitives-reduced-adrs.md) — name the facts you rely on
# - [ADR 0039](0039-single-command-human-surfaces.md) — release binder (amended: landmines synthetic, not SHA-pinned)

# # ADR 0052 — Owner OpenPGP ratification (amends 0051)
#
# - Status: Accepted
# - Date: 2026-10-11
# - Deciders: Human manager
# - Class: F (integrity / hub produce)
# - Corpus: nlc
# - Amends: [ADR 0051](0051-hub-own-produce-principles.md) (SG2 ratification model and ADR 0047 receipt replacement when wired)
# - Supersedes in part: hash-only receipt semantics in [ADR 0047](0047-adr-approval-receipts.md) and gate-set receipt rows in ADR 0051 SG2 — **when codified constraints land** (step 2); ADR 0051 file text is unchanged.
#
# ## Context
#
# RCA 5, root confirmed and remediation plan approved by the human manager 2026-10-11 (the RCA record is kept outside this repository): the two-actor principle (human manager ratifies, agents produce) was not carried into approval controls. Hash-only registries let producers rewrite stamps without the owner's act.
#
# This record **amends policy** in ADR 0051: ratification is the human manager's **clearsigned approval statement** only. Private key stays on the owner's phone (PGPony). Agents commit pasted armor **unchanged**; they never create ratification.
#
# Bootstrap trust anchor: owner Ed25519 public key, fingerprint **`9D1BD57770FC3A1DE84702750AFD22B063AE01BC`**, committed under `integrity/owner-keys/` with `integrity/owner-keys/TRUSTED_FINGERPRINTS`.
#
# ## Approval statement format (zyprompt-compatible)
#
# Each ratification uses a **plain-text statement** (clearsigned in PGPony), with these fields:
#
# ```text
# Repo: <org>/<repo>
# Document: <repo-relative path>
# Content-SHA256: <SHA-256 hex of document bytes exactly as committed>
# Decision: <must match document Status line, e.g. Accepted>
# Date: <YYYY-MM-DD>
# Summary: <one line>
# ```
#
# The signed artifact is committed **unchanged** beside the document:
#
# ```text
# <document-path>.approval.asc
# ```
#
# Example: `adrs/0052-owner-openpgp-ratification-amends-0051.approval.asc` next to this file.
#
# **Zyprompt consistency:** The document **Status** line is **Accepted** before merge. After step 2 lands, CI marks NOT_MET any document whose Status is Accepted unless a sidecar file `<document-path>.approval.asc` sits beside it and all three hold: (a) the sidecar is a valid clearsignature from a pinned fingerprint; (b) the sidecar's Content-SHA256 equals the SHA-256 of the document file; (c) the sidecar's Decision equals the document's Status. Until step 2 lands, no CI check enforces this; the PM holds the merge of any Accepted document until its sidecar is committed and the PM has verified it with an out-of-repo copy of the owner key.
#
# ## Decision
#
# 1. **Ratification SSOT:** Only the owner's clearsigned approval statement (format above) counts as ratification. No JSON hash row, registry field, or tool output substitutes.
#
# 2. **Pinned key:** Fingerprint `9D1BD57770FC3A1DE84702750AFD22B063AE01BC` is the in-force owner ratification key at adoption. Public key material lives in `integrity/owner-keys/richard-pickett.asc`; allowlist in `integrity/owner-keys/TRUSTED_FINGERPRINTS`.
#
# 3. **Key rotation / add:** A new fingerprint may enter `TRUSTED_FINGERPRINTS` only with a committed clearsigned statement **from a currently pinned key** authorizing the change, plus updated `.asc` if needed.
#
# 4. **Stamp / fitness (completion confirmation only):** After step-2 wiring, checks verify: (a) valid clearsignature from a pinned fingerprint; (b) **Content-SHA256** in the statement matches the document (or manifest) bytes in the tree; (c) **Decision** matches the document **Status**. Unsigned, wrong key, hash mismatch, tampered manifest, or **pending** → **NOT_MET**. **No tool may write a ratified entry.**
#
# 5. **Replace hash-only receipts:** Supersedes ADR 0047 hash-only JSON and ADR 0051 SG2 hash-only gate-set receipts **when implemented** — same OpenPGP sidecar model for ADR files and gate-set batches (manifest + single-line signature when many paths).
#
# 6. **PM independent verify:** At each review and release, the PM re-verifies signatures with an **out-of-repo copy** of the owner public key (not only CI), before treating ratification as real.
#
# 7. **Verifier implementation (step 2, not this PR):** Python-first hub verifier, self-contained: import key from `integrity/owner-keys/`, pin against `TRUSTED_FINGERPRINTS`, verify sidecars via **GnuPG** (`gpg --verify`) or **Sequoia** (`sqv`); choose simplest dependable option in implementation PR.
#
# 8. **Bootstrap:** First in-force ratification under this ADR is the owner's clearsigned statement for **this document** at PR head bytes, committed as this file's `.approval.asc`.
#
# ## Consequences
#
# - ADR 0051 remains Accepted; its ratified text and existing stamps are untouched.
# - Version class **minor** when fully wired.
# - Step 1 (this ADR + keys only): no fitness or receipt changes until owner signs and step 2 lands.
#
# ## Rejected
#
# - Hash-only approval receipts as ratification evidence.
# - Producer or maintainer tools that set ratified/pending registry state without a sidecar.
# - Any retired or unpinned key fingerprint in `TRUSTED_FINGERPRINTS`.
#
